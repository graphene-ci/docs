# Подключение к инсталляции

**Context** Studio — именованное подключение из четырёх значений: server,
token, переопределение namespace и разрешение plain HTTP для адреса без схемы.
Contexts позволяют одной Studio переключаться между независимыми инсталляциями
Graphene, не смешивая их состояние.

## Добавить context

Откройте переключатель contexts, выберите **Add context** и укажите:

| Поле | Значение |
|---|---|
| Server | `host:port` или полный `http(s)://` URL. Пустое значение означает origin, с которого загружена Studio. |
| Token | Bearer token. Если оставить пустым, Studio запросит его при входе и не сохранит. |
| Namespace | Необязательное переопределение. Оставьте пустым, если namespace закреплён в token. |
| Insecure | Включает plain HTTP для адреса без схемы. Допустимо только в доверенном локальном dev-стеке. |

Studio проверяет context и вызывает `WhoAmI`. Успешная проверка определяет
principal, доступный namespace, роль и permissions, которые показывает UI.
Неверный token, недоступный server или запрещённый namespace оставляют context
в состоянии ошибки, не переключая его молча на другую инсталляцию.

## Хранение и доверие

Web-приложение хранит сохранённые contexts в профиле браузера. Считайте профиль
с token хранилищем учётных данных: не сохраняйте привилегированные tokens на
общем компьютере. Desktop-сборка использует тот же renderer и публичный
Management API; отдельной границы доверия у неё нет.

Для удалённой инсталляции завершайте TLS на сервере или доверенном proxy и
используйте адрес `https://`. Plain HTTP раскрывает сети token и весь трафик
Management API.

## Namespace и permissions

Смена выбранного namespace меняет scope запроса к API, но не добавляет прав,
которых нет у token. Studio определяет доступные действия из `WhoAmI`, а сервер
независимо авторизует каждый запрос.

См. [безопасность и доступ](../operations/security.md) о ролях и scope token и
[протокол Management API](../api/protocol.md) о заголовках каждого запроса.
