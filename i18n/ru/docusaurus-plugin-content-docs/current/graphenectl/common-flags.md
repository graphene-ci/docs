# Флаги подключения

Каждая сетевая команда принимает эти три. Они выбирают, **куда**
команда говорит и **от чьего имени**; [формы вывода](outputs.md)
выбирают, как рендерится ответ.

| Флаг | Тип | Дефолт | Что делает |
|---|---|---|---|
| `--context <name>` | строка | `current` из конфига | использовать этот контекст для одного вызова |
| `--config <path>` | строка | `$GRAPHENE_CONFIG`, иначе `~/.config/graphene/config.yaml` | читать контексты из этого файла |
| `-n, --namespace <ns>` | строка | неймспейс контекста | неймспейс одного вызова — осмыслен для кластерных admin-токенов (`*`); токен с неймспейсом сервер пинит к его собственному скоупу |

## Примеры

Один вызов к другой инсталляции без переключения:

```console
$ graphenectl get run --context prod
```

CI-джоба со своим файлом конфигурации:

```console
$ graphenectl run list --config ./ci/graphene.yaml
```

Admin-токен смотрит другой неймспейс:

```console
$ graphenectl get all -n team-b
```

Полная цепочка разрешения — файл, контекст, оверлеи окружения —
описана в [Контекстах](contexts.md).
