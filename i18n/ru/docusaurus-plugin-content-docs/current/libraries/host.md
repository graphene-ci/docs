# Host

Библиотека host превращает настройки машины в ресурсы: параметры ядра, атрибуты
`/sys`, каталоги и юниты systemd на машине агента. Каждая настройка — запись в
дереве. Её finalize возвращает машину в то состояние, в котором запись её
застала. Прогон, который меняет машину только через такие записи, после своего
каскада оставляет машину в исходном состоянии.

```go
import hostlib "github.com/graphene-ci/library/host"

db := pipeline.NewAgent(ctx, "db")
hostlib.Sysctl(ctx, db, "db", map[string]string{
    "vm.swappiness":      "10",
    "net.core.somaxconn": "4096",
})
hostlib.Sysfs(ctx, db, "/sys/kernel/mm/transparent_hugepage/enabled", "never")
hostlib.UnitState(ctx, db, "unattended-upgrades.service", hostlib.UnitMasked)
data := hostlib.Dir(ctx, db, "/data/pg", hostlib.DirAccess{Mode: 0o700, UID: 999, GID: 999})
path := data.Ready(ctx).Path // bind mount в контейнер базы
```

| Конструктор | Пока запись жива | При удалении |
|---|---|---|
| `Sysctl(ctx, agent, name, values)` | значения действуют и лежат в `/etc/sysctl.d/90-graphene-<record>.conf` | drop-in удаляется, каждому ключу возвращается прежнее значение |
| `Sysfs(ctx, agent, path, value)` | атрибут держит `value` | записывается прежнее значение |
| `Dir(ctx, agent, path, access)` | каталог существует с заданными правами и владельцем | каталог удаляется вместе с содержимым |
| `Unit(ctx, agent, name, content)` | файл юнита лежит в `/etc/systemd/system`, юнит включён и запущен | юнит останавливается, выключается, файл удаляется |
| `UnitState(ctx, agent, name, want)` | существующий юнит удерживается в `UnitStopped`, `UnitDisabled` или `UnitMasked` | возвращается прежнее состояние: unmask, enable, start — как было |
| `Mount(ctx, agent, MountRequest{...})` | устройство смонтировано в точку монтирования через systemd mount-юнит (переживает перезагрузку) | файловая система размонтируется, юнит удаляется; данные остаются |

`Unit` готов, только когда юнит активен: `systemctl enable --now` возвращает 0
и при неудачном старте, поэтому запись проверяет сама. Oneshot-сервису нужен
`RemainAfterExit=yes`, чтобы считаться работающим.

## Диски

`Mount` называет устройство — лучше по имени из `/dev/disk/by-id`: факты агента
перечисляют каждый физический диск с его id, размером, моделью и серийным
номером. С `Format: true` файловая система создаётся только на **пустом**
устройстве; устройство с чем угодно — другой ФС, таблицей разделов —
отвергается с `host_conflict` и никогда не форматируется поверх. Удаление
никогда не стирает данные. На машине, которую подготовил кто-то другой,
`Check: true` только проверяет, что устройство смонтировано там с этим типом, и
ничего не меняет — ни сейчас, ни при удалении:

```go
data := hostlib.Mount(ctx, db, hostlib.MountRequest{
    Device:     "/dev/disk/by-id/nvme-SAMSUNG_MZQL23T8HCLS-00A07_S64HNE0R123456",
    Mountpoint: "/data",
    FSType:     "xfs",               // ext4, xfs или btrfs
    Options:    []string{"noatime"},
    Format:     true,                // только пустое устройство
})
```

## Захваты

Запись захватывает то, что меняет, маленьким файлом в
`/var/lib/graphene-host/claims` на машине. В захвате сохраняется прежнее
значение до любых изменений, поэтому запись, у которой прервалась
инициализация, всё равно восстанавливает машину. Две записи не могут держать
один ключ sysctl, атрибут sysfs, каталог или юнит: вторая падает со стабильным
типом ошибки `host_conflict`. Тот же код отказывает `Dir`, если путь уже
существует, и `Unit`, если файл юнита уже есть. Запись никогда не владеет
данными, которые не создавала.

`sysctl --system` не восстанавливает значения: ключ, не названный ни в одном
файле, сохраняет текущее значение. Поэтому запись сама возвращает каждое
прежнее значение.

## Удаление

Снятие настройки повторяет временный сбой до двух минут и затем отпускает
запись: уже исчезнувшая машина не может заблокировать каскад. Каталог сначала
переименовывается в соседний `.graphene-trash` — это мгновенно при любом
размере — и затем удаляется. Удаление может идти до двух часов с heartbeat;
то, что прерванная очистка не успела, остаётся в корзине, а не под путём
записи.

## Ограничения

- Значение `Sysfs` не переживает перезагрузку. Значение `Sysctl` переживает
  через свой drop-in.
- `UnitState` меняет вендорские юниты, поставленные в `/usr/lib/systemd`.
  systemd не умеет маскировать юнит, чей файл лежит в `/etc/systemd/system`.
- `UnitMasked` для ещё не существующего юнита всё равно его маскирует: пока
  запись жива, юнит не запустит ничто установленное позже.
- `EnvironmentFile`, на который ссылается `Unit`, — ресурс [File](file.md).
- Пути файловой системы не выходят за корень машины: симлинк, ведущий наружу,
  роняет запись, а не даёт ей писать туда. Симлинк, подложенный на место
  файла записи, заменяется, а не разыменовывается; каталог, подменённый
  симлинком, роняет запись, а не меняет цель симлинка.
- `Dir` требует Linux 5.6 или новее: ядро само разрешает путь каталога без
  симлинков (`openat2`), прежде чем меняются права и владелец.

Свой агент владеет своими host-записями, и они уходят вместе с агентом. На
подключённом агенте записи принадлежат прогону и удаляются в его конце, если
их не передали.

## Тесты

`host/hosttest` моделирует объявления для
[локальных тестов пайплайна](../sdk/testing.md): каждая настройка становится
готовой записью под своим владельцем, машина не затрагивается.
